# US-04 — Especificación B1 y contratos RED

Nota: este documento conserva la evidencia histórica de B1. El estado final y
las garantías verificadas se describen en [us04.md](us04.md).

Estado: RED; no hay implementación del servicio ni de persistencia. Los puntos de
entrada Abrir devuelven ErrPendiente para compilar y observar fallos conductuales,
sin reglas bancarias, lectura, escritura ni bloqueo productivos.

## Alcance aprobado

- PEN, int64 en céntimos; montos positivos, finitos y con hasta dos decimales.
- Máximo representable: 92233720368547758.07 PEN. Rechazar también cualquier abono
  cuyo saldo resultante desborde int64. No redondear ni truncar entradas.
- Documento JSON versión 1 con identidad de cuenta, moneda, saldo inicial,
  saldo actual e historial ordenado. El saldo inicial permite validar la cadena.
- IDs únicos de cuenta, solicitud y transacción. La cuenta se proporciona al abrir;
  el servicio usa un generador inyectado para transacciones. Solicitudes proceden
  del llamador y conservan su ID durante los reintentos.
- Reloj inyectable; fecha UTC. Secuencia creciente por registro.
- Cada rechazo de negocio se persiste con motivo y saldo intacto. Monto nullable
  cuando la entrada no representa una cantidad admitida; nunca serializar NaN.
- Rechazo de negocio: Transaccion RECHAZADA y error nil si pudo confirmarse.
  Error técnico: error no nil; no anunciar éxito ni asegurar registro del intento.
- Mismo ID y mismos datos: devolver resultado original, incluso tras reiniciar.
  Mismo ID con datos diferentes: ErrConflicto, sin nuevo movimiento o registro.
- Estado() devuelve una copia aislada del último estado confirmado.
- Exclusión de escritor para toda la vida de Archivo; Cerrar libera el recurso
  y debe tolerar llamadas repetidas. Sin mutex compartido entre procesos como
  sustituto del bloqueo del sistema operativo.

## Contratos

internal/banco: Solicitud, Transaccion, Estado, Opciones, Almacen y Operador.
Abrir carga o inicializa el estado; no sobrescribe un estado existente con el
saldo inicial del llamador. Operar coordina validación, candidato y confirmación.
ErrPersistencia indica fallo sin confirmación; ErrIncierto exige reconciliación
y bloquea operaciones posteriores hasta reabrir. ErrCorrupto rechaza recuperación.

internal/persistencia: Abrir(ruta) adquiere exclusión; Archivo implementa Cargar,
Confirmar y Cerrar. Cargar devuelve os.ErrNotExist si aún no hay documento.
Confirmar recibe el documento completo, nunca saldo e historial por separado.
La validación de corrupción puede ocurrir al abrir o al cargar.

## Estrategia pendiente de validar en Windows

Preparar copia candidata, escribir temporal en el mismo volumen, comprobar
escritura completa, Sync y Close; confirmar mediante un adaptador Windows con
recuperación explícita. No borrar primero el estado anterior. No dar por atómico
os.Rename: Go lo advierte para plataformas no Unix.
ReplaceFileW tiene estados de fallo que requieren reconciliación y su opción
REPLACEFILE_WRITE_THROUGH no está soportada. La creación inicial es otro caso.

Tras resultado incierto, reconciliar documentos por versión, secuencia, IDs e
invariantes; nunca elegir solo por fecha. No afirmar resistencia a cortes eléctricos
ni atomicidad Windows hasta ensayar el protocolo real. El doble de pruebas simula
fallos antes y después del efecto persistente; no demuestra garantías del SO.

Fuentes:
- https://go.dev/pkg/os/#Rename
- https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew

## Matriz de pruebas B1

- Servicio: retiro, abono, rechazo, metadatos, montos inválidos, fallo de escritura
  de éxito/rechazo, idempotencia/conflicto, dos retiros concurrentes con barrera,
  confirmación incierta con/sin efecto y reconciliación.
- Almacenamiento real futuro: documento JSON y reapertura con idempotencia,
  corrupción sintáctica/versión/cadena de saldo, exclusión y liberación, ruta inválida.
- TempDir aísla archivos. Reloj e IDs controlados; sin sleeps ni dependencias.
- Gherkin es especificación documental: no existe ejecutor de pasos instalado.

Pendientes para GREEN: fallos por fase de escritura/Sync/Close/reemplazo, interrupción
real de proceso, prueba de exclusión entre procesos distintos, generación real de IDs
y copias defensivas. B1 incluye exactitud decimal y desbordamiento de saldo.
La reapertura B1 simula reinicio liberando y
reabriendo recursos en el mismo proceso; no ejecuta un proceso nuevo.

No cambiar originales, pruebas previas o CLI. Toda futura edición de un archivo
preexistente requiere explicar necesidad y obtener aprobación antes de editarlo.
